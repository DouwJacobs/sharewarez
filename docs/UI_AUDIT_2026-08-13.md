# UI consistency follow-up audit

Audit date: 2026-08-13
Branch: `main`
Application: local WSL development instance at `http://localhost:5006`
Viewports: desktop application viewport and mobile 390 × 844
Theme observed: Ember/custom warm dark theme

This is the active checklist for UI consistency work after the original
`UI_AUDIT.md`. The audit was read-only: no forms, destructive actions, theme
settings, or application files were changed while collecting the findings.

## Coverage

The following representative routes were inspected at desktop and mobile widths:

- User: `/discover`, `/library`, `/requests`, `/downloads`, `/notifications`,
  `/favorites`, `/trailers`, `/help`, and one populated `/game_details/<uuid>`.
- Account: `/settings_profile_view` and `/settings_panel`.
- Administration: `/admin/dashboard`, `/admin/libraries`,
  `/admin/scan_management`, `/admin/integrations`, `/admin/statistics`, and
  `/admin/system_logs`.

Checks covered document overflow, the single mobile gutter, content width,
surface hierarchy, headers and actions, tables, horizontal rails, fixed mobile
navigation, empty/loading/error states, theme propagation, semantic colors,
and representative rendered screenshots.

No audited page produced document-level horizontal overflow at 390 px. Modern
`.app-page` routes generally preserved the intended single 12 px mobile gutter,
and the fixed bottom navigation did not cover the end of page content.

## P0 — Functional blockers

- [x] **Repair Discover.** `/discover` returned HTTP 500 at both viewport sizes.
  Diagnose this before visual refinement because it is the authenticated landing
  page and prevents auditing its current carousel, collections, and activity UI.
- [x] **Remove the remaining redundant library label.** The game-details hero
  still renders `In your library`, despite the product containing no non-library
  game surface. The earlier cleanup removed `In library` elsewhere but missed
  this variant.

## P1 — Mobile usability

- [x] **Replace the mobile Libraries table presentation.** At 390 px,
  `/admin/libraries` initially shows only the library-name column. Game count and
  the action menu are off-screen behind a subtle horizontal scrollbar. Prefer a
  compact library card/row with identity, platform, count, and actions immediately
  visible. If a table is retained, keep identity/actions sticky and hide lower-value
  columns intentionally.
- [x] **Increase mobile Library information density.** `/library` uses one very
  large poster per row, producing roughly 6,600 px of page height for 16 games.
  Default mobile browsing should use a two-column compact grid; a spacious
  single-column mode can remain a future user preference.
- [x] **Make Scan Management categories discoverable.** The horizontal mobile tab
  rail clips later labels and gives a weak indication that more categories exist.
  Evaluate a compact category selector, wrapped tabs, or clear edge gradients and
  scroll affordances.
- [x] **Expose every Profile destination.** The Profile/Preferences/API-token rail
  clips the third destination. Use a three-item segmented control, wrapped rail,
  or mobile select.
- [x] **Reduce prominence of destructive log maintenance.** On mobile System Logs,
  `Clear logs` becomes the most visually dominant full-width action. Move it away
  from routine filters and retain danger semantics without making it the page's
  apparent primary action.
- [x] **Normalize the Trailers mobile shell.** Trailers omits the standard mobile
  search/account header and therefore feels detached from the rest of the app.
  Its error state should explain whether retrying is useful and offer consistent
  recovery actions.

## P1 — Shared page structure

- [x] **Adopt explicit content-width tiers.** Use and document three intentional
  rails rather than route-specific widths:
  - narrow for profile/settings forms;
  - standard for requests, notifications, and help;
  - wide for library grids, logs, tables, and scan management.
- [x] **Standardize header and primary-surface composition.** The current empty
  state pages use three patterns: Downloads nests its header inside the content
  surface, Favorites makes the entire page a surface, and Notifications places a
  page header above one content surface. Prefer the Notifications structure for
  ordinary list/inbox pages.
- [x] **Finish migration to the responsive layout contract.** Remaining templates
  that bypass `.app-page` and/or `.app-page-header` include Game Identify/Edit,
  Scan Management, Game Request Details, Newsletter, Discovery Sections, older
  Discord/settings pages, Profile Edit, and Invitations.
- [x] **Prevent incomplete first paint on script-heavy workspaces.** Scan Management
  briefly presents a dim/empty active panel before Bootstrap/tab scripts settle.
  Render the server-selected panel visibly or use a deliberate loading state.

## P2 — Content presentation improvements

- [x] **Use deliberate missing-cover placeholders.** Several Library cards render
  as empty dark poster panels. Use the shared branded/default cover or a purposeful
  fallback containing an icon/title; do not resemble an unloaded card indefinitely.
- [x] **Tighten the Requests search surface.** Desktop Requests dedicates a large
  surface to one search input. Consider combining it with the page header or
  reducing its vertical footprint.
- [x] **Simplify mobile request-card hierarchy.** Keep title and status in one
  predictable header, metadata below, and actions in one final row so edition,
  status, edit, view, and withdraw controls do not compete.
- [x] **Improve the Libraries desktop representation.** A single-row table spreads
  sparse information across a very wide surface. A library card/list can show
  artwork, platform, game count, recent scan health, and the action menu more
  effectively.
- [x] **Strengthen Help hierarchy.** Keep the useful accordion pattern but adopt
  the standard eyebrow/title/description header and make inactive/secondary copy
  less visually subdued.
- [x] **Reduce Admin dashboard vertical travel.** The two-column mobile tool grid
  works well. Slightly tighter section spacing and ordering by operator frequency
  would make the dashboard faster without changing its successful structure.
- [x] **Keep game-details content focused.** The mobile hero is readable and has no
  horizontal overflow, but the very large cover consumes most of the first viewport.
  Reassess the poster height when compact/spacious layout preferences are added.

## P1 — Theme consistency

The Ember palette propagates successfully through modern Library, Requests,
Notifications, Integrations, and Admin dashboard surfaces. The largest remaining
risk is legacy CSS that hard-codes a different palette instead of using theme
tokens.

- [x] **Define shared semantic theme tokens** for success, warning, danger,
  information, two muted-text strengths, selected/hover surfaces, table headers,
  table rows, empty states, error states, and destructive actions.
- [x] **Migrate `random_trailers.css`.** It contains approximately 46 hard-coded
  colors and no theme variables. The yellow error treatment is not shared with
  other application error states.
- [x] **Migrate `admin_manage_scanjobs.css`.** Approximately 131 hard-coded color
  values versus 18 theme-variable references leave its tables and workspace prone
  to blue-gray/default styling inside warm or light themes.
- [x] **Migrate `admin_access_management.css`.** Approximately 106 hard-coded
  values versus 8 theme-variable references.
- [x] **Migrate `admin_system_logs.css`.** Approximately 64 hard-coded values
  versus 11 theme-variable references; normalize table headers, severity cards,
  filters, and danger actions.
- [x] **Remove token-free legacy component palettes.** Prioritize
  `admin-common.css`, `table-polish.css`, `table-components.css`,
  `admin_background_jobs.css`, `admin_server_status.css`,
  `admin_manage_extensions.css`, `user_invites.css`, and `game_status.css`.
- [x] **Audit high-volume mixed files carefully.** `base.css`,
  `game_details.css`, `requests.css`, `theme-components.css`, and `sidebar.css`
  contain many hard-coded values alongside tokens. Distinguish structural alpha
  treatments from colors that should express the active theme; do not perform a
  blind mechanical replacement.
- [x] **Normalize legacy table colors.** Some admin tables still introduce cool
  blue-gray headers and Bootstrap-dark row colors that conflict with Ember's warm
  palette. All tables should derive header, row, border, hover, and muted text from
  shared tokens.
- [x] **Normalize empty/loading/error states.** Downloads, Favorites,
  Notifications, Trailers, Statistics, and script-heavy admin pages should share
  icon, copy, surface, and recovery-action treatments.
- [x] **Verify multiple theme families after migration.** Re-run the route set with
  the default theme, one warm/dark theme, one cool/dark theme, and a light or
  high-luminance theme. Check contrast, native controls, modals, tables, focus
  rings, status chips, and destructive actions. Ember, Evergreen, and Midnight
  Cyan were verified; no light theme is installed in the development instance.

## Recommended implementation order

1. Repair Discover and remove the remaining `In your library` copy.
2. Fix mobile Libraries actions and the clipped Profile/Scan navigation rails.
3. Standardize page shells, width tiers, headers, and content surfaces.
4. Add the denser two-column mobile Library layout and deliberate missing covers.
5. Normalize empty, loading, and error states.
6. Introduce the missing semantic theme tokens and migrate the highest-risk legacy
   CSS files in focused batches.
7. Polish lower-priority page-specific density and hierarchy.
8. Add screenshot regression coverage for the representative audit routes at
   desktop and 390 × 844 mobile widths.

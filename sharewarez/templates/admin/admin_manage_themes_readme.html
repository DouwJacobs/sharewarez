Package structure

Upload a ZIP whose contents begin at the archive root. Do not wrap the files in an extra theme directory.

Correct

my-theme.zip
├── theme.json
├── css/
│   ├── base.css
│   ├── components.css
│   ├── admin/
│   ├── games/
│   └── site/
├── js/          # optional
└── images/      # optional

Incorrect

my-theme.zip
└── my-theme/
    ├── theme.json
    ├── css/
    └── js/
Upload limits: ZIP format, maximum 25 MB. Theme names cannot contain path separators, traversal sequences, Windows reserved names, or characters such as < > : " | ? *.

Theme metadata

theme.json must contain the four required fields below. version is recommended but currently optional.

{
  "name": "Your Theme Name",
  "author": "Your Name",
  "description": "A short description",
  "release_date": "2026-08-01",
  "version": "1.0.0"
}

The theme name becomes its installed directory name after filesystem-safe normalization. Choose a stable, unique name.

Partial themes and asset fallback

The css/ directory is required, but you do not need to copy every default asset. Templates request assets through the theme_asset filter:

{{ "{{ 'css/components.css'|theme_asset }}" }}

If that relative path exists in the selected theme, {{ site_title }} uses it. Otherwise it falls back to the same path in the default theme. This makes small, maintainable override themes possible.

  • Mirror the exact relative path of every asset you override.
  • Start with color, typography, and surface overrides in css/base.css or css/components.css.
  • Add page-specific files only when that page needs structural changes.
  • JavaScript is optional and should be overridden only when behavior must change.
Trusted code: Installed theme JavaScript runs in users’ browsers with the application’s origin. Only install themes from authors you trust, and review custom JavaScript before uploading.

Install, select, and test

  1. Create theme.json and at least a css/ directory.
  2. ZIP the directory contents at the archive root.
  3. Open Themes and install the ZIP.
  4. Select the theme from user preferences, then hard-refresh the browser.
  5. Test desktop and mobile layouts with both user and administrator accounts.

During default-theme development, DEV_MODE=true recopies bundled theme files during application startup. {{ site_title }} does not hot reload these files, so restart with ./startweb.sh after changes.

Restore defaults: “Restore default theme” replaces the installed default-theme directory with the bundled source. Any direct modifications to the installed default theme are overwritten.

Compatibility checklist

  • Sidebar expanded and collapsed
  • Centered global search and result palette
  • Game cards and game details
  • Tables with horizontal overflow
  • Forms, validation, and file inputs
  • Admin headers and action buttons
  • Modals, confirmations, and toasts
  • Keyboard focus indicators
  • Mobile widths at 768 px and below
  • prefers-reduced-motion behavior
